# 给 SOL：设计“单次输入完成 Anima 配置”的方式

请把本文件和另外三份 Anima/Izumi SKILL 文件一起阅读。你的任务不是泛泛解释 Anima，而是告诉我：**我应该如何一次性向扩展里的“按 SKILL 新手版配置”助手表达需求，让它直接生成完整的、属于我的 Anima 配置方案，而不是一题一题询问。**

## 我的目标

我希望配置助手支持两种模式：

1. **新手逐问模式**：保留现在的“一次只问一个基础问题”。
2. **一次性配置模式**：我一次性提交一段自然语言说明，助手读取当前脱敏配置后直接生成完整方案；只有遇到会导致方案完全不同、且无法从当前配置或我的文字推断的关键事实时，才允许追问。

一次性模式不是“只生成建议”，而是必须生成可由前端本地执行器校验和应用的 `CONFIG_PLAN`。

## 一次性输入必须能够表达的内容

请设计一个用户可直接复制的中文模板，至少包含以下部分。每一项都允许用户用自然语言填写，不要要求用户填写技术数字：

```text
【配置模式】一次性完成

【我的 RP 类型】例如：长期恋爱、日常陪伴、战斗成长、原作还原、混合

【我最想长期记住的内容】例如：承诺、关系变化、共同习惯、重要第一次、角色性格变化、世界观、技能和战斗结果

【我不希望被记住或不希望召回的内容】例如：临时玩笑、重复寒暄、思维草稿、状态栏原始文本

【User 消息是否作为长期记忆】要/不要，并说明原因

【原作或外部资料】有/没有；如果有，我会通过文件选择器选择 TXT、MD 或 JSON。请不要要求我把全文粘贴给 AI。

【当前卡是否有外部状态系统】MVU/EJS/其他/没有/不确定

【Anima 状态变量】如果有外部状态系统，默认关闭；否则按我的目标决定是否启用

【知识库】是否启用、资料用途、是否绑定当前角色

【召回偏好】少而准/平衡/尽量完整；不要让我填写 base_count、candidate_multiplier 等数字

【总结偏好】自动总结频率、总结详细程度、是否保留长期关系证据

【上下文预算】如果我没有提供上下文长度，请从当前脱敏 API readiness 或现有配置判断；不能编造 API 信息

【API 规则】API 地址、端口、模型名和 API Key 以 Anima 设置面板当前值为准；不要询问、生成、猜测或修改密钥和地址

【其他偏好】任何我希望 Anima 长期遵守的记忆/检索规则
```

## 助手必须完成的事情

请你为这个一次性模板设计一套明确规则，使助手能够一次性完成：

- 记忆目标分类和 Summary 配置；
- Summary prompt、标签契约、重要标签与特殊标签的划分；
- User 记忆/代理权策略；
- 向量检索开关和完整的分布式检索策略；
- `strategy_settings`、`injection_settings`、标签 `count`、`diversity`、候选倍数、预重排预算、上下文安全预算；
- BM25 开关、词典策略、检索预算和必要的重建/标脏动作；
- Rerank 是否启用以及对应的非敏感设置；
- 知识库开关、导入文件用途、库绑定、向量/BM25 写入策略和注入位置；
- MVU/EJS/其他变量系统检测、状态变量冲突处理和状态提示词；
- global / character / chat 作用域；
- 当前实际配置的 Diff；
- Schema、安全扫描、未知字段保留、读回验证、回滚和风险报告。

不能只告诉我“请去某个页面把某参数改成某数值”。我要的是：AI 生成完整的非敏感配置计划，前端校验后由我确认，再自动写入。

## 一次性模式的对话规则

请明确规定：

1. 用户选择“一次性完成”后，助手不应从 Q1 开始重新问问卷。
2. 助手先读取当前 `DISCOVERY_CONTEXT`，再解析我的整段输入。
3. 能从输入、当前配置或能力快照推断的内容不得追问。
4. 能安全采用默认值的内容应采用符合 SKILL 的默认值，并在方案 Diff/说明中标注。
5. 只有关键事实缺失且会改变安全或作用域的情况下才追问，例如无法判断是否存在外部状态权威、无法判断是否允许导入文件、或没有当前角色却要求角色绑定。
6. 如果必须追问，最多一次只问一个真正阻塞的问题；回答后继续生成完整方案，不重新开始。
7. 不询问 API Key、Token、Cookie、Password、Authorization，也不要求用户粘贴原作全文。
8. 不能声称“已经配置完成”，除非本地执行器已经 Apply 并 Readback 验证成功。
9. 方案必须覆盖所有可设置的非敏感字段，不能因为一次性模式就遗漏向量分布式检索、BM25、知识库或状态变量。

## 请 SOL 最终交付

请按下面结构输出，不要只给原则：

### A. 可直接粘贴给配置助手的最终中文模板

模板要能让普通用户一次性填写。请保留清晰的占位符，并说明哪些内容可以写“自动判断”。

### B. 助手收到模板后的内部执行规则

用接近可执行 SKILL 的形式写出：解析字段、默认值、冲突优先级、何时追问、如何生成完整 CONFIG_PLAN、如何处理文件选择器和外部状态系统。

### C. CONFIG_PLAN 完整性清单

逐项列出必须出现或必须检查的模块，尤其不能漏掉：

- Summary 和标签契约；
- RAG 的分布式检索策略、注入设置、候选预算和标签联动；
- BM25；
- Rerank；
- 知识库；
- 状态变量；
- global/character/chat 作用域；
- API 依赖但不含 API 凭据；
- 数据库动作、Diff、确认、Apply、Readback、Rollback。

### D. 需要修改插件的地方

请具体到模块/函数/状态字段，说明如何在现有“逐问模式”旁边增加“一次性模式”，而不是破坏现有模式。

### E. 测试用例

至少覆盖：

- 一次性长文本直接生成 ready 方案；
- 只有一个关键事实缺失时只问一个问题；
- 检测到 MVU/EJS 时不会误开 Anima 状态；
- 没有原作文件时关闭知识库并解绑当前角色；
- 选有文件时不会把文件全文发给 AI；
- CONFIG_PLAN 包含完整分布式检索和 BM25 字段；
- 不会出现 API key/token 等秘密字段；
- 记录保存在当前聊天本地而不进入远程设置同步；
- 删除记录后无法恢复旧对话；
- 关闭再打开或刷新后能恢复对话。

### F. 最终建议的用户操作文案

请给出扩展界面上“一次性配置”按钮、输入框、确认 Diff 和历史记录按钮的中文文案。
