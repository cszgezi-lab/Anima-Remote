# 手机与朋友使用指南

## 你需要安装什么

每台 TauriTavern 设备只安装客户端依赖：

1. 安装并启用 TavernHelper。
2. 在 TauriTavern 的扩展管理器中从 Git 安装本项目仓库根目录（根目录 `manifest.json` 会加载 `extension/` 中的前端）。
3. 在 Anima 的连接区填一次服务器 HTTPS MagicDNS 地址和自己的 token。

服务器端不需要在 TauriTavern 手机里安装 Node.js、npm 或 SillyTavern 服务端插件。扩展会保留原 Anima 的面板、自动化和设置语义；远程连接区只是新增服务器地址、token、连接测试和超时等少量选项。

## 首次连接

在扩展的远程连接设置中填写：

```text
服务器地址: https://<machine-name>.<tailnet>.ts.net
Token: <由服务器管理员单独交给你的 token>
```

点击“测试连接”，看到 `/v1/me` 成功后保存。不要填服务器本机的 `http://127.0.0.1:18000`，也不要填未经 HTTPS 的 Tailnet IP。Android release 会阻止 cleartext HTTP。

连接成功后，正常使用原来的 Anima 功能即可：

- **记忆/RAG**：写入、查询和删除聊天记忆；服务器保留热索引，手机刷新不会重新构建整个索引。
- **BM25**：关键词和中文分词检索，适合精确人名、标签和时间线查询。
- **知识库**：导入和检索知识库；每个用户的库与其他 token 隔离。
- **总结与状态**：按原有自动化在生成前后运行。配置保留原来的全局、角色、聊天优先级。
- **API 设置**：为总结、状态、向量和重排分别选择供应商。提供商密钥不通过设置同步回传；按扩展界面提示在受保护的位置配置。
- **日志/调试**：用于确认连接和检索步骤，不要把 token、API key、Cookie 或完整请求体发给朋友。

## 配置助手

API 设置顶部提供“Anima 配置助手”。它按长期 RP / MVU 适配规则逐步询问：

1. 你希望长期记住什么，以及关系、角色、世界观、技能或战斗等重点类别。
2. 是否有原作 TXT、MD 或 JSON；选择文件后，助手会逐个构建知识库并绑定到当前角色卡。
3. 当前角色卡是否使用 MVU、EJS 或其他变量系统；如果有，助手会关闭 Anima 状态变量，避免双重状态源。
4. 是否保留 User 消息；长期恋爱 RP 默认保留，以免丢失用户的承诺、边界和主动选择。

确认前会显示预览。没有原作资料时，助手会关闭知识库；使用外部变量系统时，助手会关闭 Anima 状态变量，但不会删除已有数据库或聊天记录。助手会自动设置长期总结、前文总结数量、过滤规则、向量检索、BM25 和关系类分布式召回；API Key 和 Token 不会写入总结提示词。

## API 怎么配置

Remote 只把 Anima 的 RAG/BM25 后端移到服务器；模型提供商仍沿用原 Anima 的四张配置卡。第一次使用时在“API 设置”依次配置：

1. **总结模型**：长上下文聊天模型，用于阶段总结；重质量，可降低调用频率。
2. **状态模型**：聊天模型，用于回复后的状态更新；优先低延迟、低思考。
3. **向量模型**：只能选 Embedding 模型；更换后必须重建旧向量库。
4. **重排模型**：可选 Rerank 模型；提高召回排序，通常不要求重建库。

每张卡按“API 类型 → 基础 URL → API Key → 获取/填写模型 ID → 测试 → 保存”的顺序。公开 OpenAI 兼容服务一般填其 `/v1` 基址；Rerank 卡按供应商要求填写完整 rerank 地址。若使用服务器现有 `vertex2openai`，可把聊天类卡指向 `http://100.96.176.24:8050/v1`，但管理员必须先按部署文档精确放行该私网主机。

提供商 API Key 保存在当前 TauriTavern 设备的本地设置中，请勿使用公共设备。它会通过 Anima Remote 的 HTTPS 连接随该次代理请求送到服务器并转发给提供商，但会从远程设置同步、服务端设置文件和普通日志中剔除。因此换手机或给朋友安装时，服务器 URL 与非敏感设置可以恢复，提供商密钥仍需在各自设备上单独填写；朋友不应使用 owner 的 Anima token。

## 设置和数据如何隔离

服务端从 bearer token 推导租户，不接受客户端自己提交的 tenant ID。下面三层设置仍按原 Anima 语义生效：

```text
用户全局 < 角色覆盖 < 聊天元数据
```

所以你和朋友可以使用同名角色、同名聊天甚至同名 collection，而不会因为名字相同互相看到记忆。设置同步按 `global`、`character`、`chat` 分开保存；网络暂时失败时，本机缓存仍先生效，恢复连接后再同步。

不要多人共用一个 token。共用 token 会被服务器视为同一租户，届时记忆和设置就会合并，这是权限结果，不是冲突解决功能。

## 给朋友使用

管理员需要完成两件事：

1. 将朋友的设备加入同一 Tailnet，并在 grants 中只允许其访问 `tag:anima-server` 的 `tcp:443`。
2. 为朋友创建独立 token，只通过私密渠道交付。

朋友在自己的手机上安装 Tailscale、TavernHelper 和 Anima 扩展，填管理员给的同一个 HTTPS MagicDNS 地址与自己的 token。朋友不需要你的 token，也不需要接触服务器 Shell。

朋友离开时，管理员应同时从 Tailnet grants 移除其身份，并按 token ID 撤销其 Anima token。只撤销其中一层会留下不必要的访问面。

## 刷新后很久才初始化

正常网页刷新不会重启服务器容器，也不会重建服务器索引。按这个顺序判断：

1. 确认 Tailscale 在线，MagicDNS 地址仍能打开。
2. 在扩展设置中确认服务器地址仍是 `https://`，token 没有被浏览器清空。
3. 查看服务器管理员是否能从本机访问 `/healthz`；健康时不要反复重启 Docker。
4. 确认 TavernHelper 已启用并且没有被 TauriTavern 更新禁用。
5. 只做一次强制刷新；不要在每次刷新时手动执行服务器重启或重建索引。

若仅某个超长聊天慢，先用新聊天对照；不要为了加速直接删除旧聊天。若每次都超过约 15 秒，记录扩展控制台的第一条错误、失败的 Network URL 和服务器端对应时间点日志，但不要包含认证头或请求体。

## 常见错误

| 现象 | 处理 |
| --- | --- |
| `401` | token 缺失、复制错误或已撤销；让管理员按 token ID 核对，不要索要 owner token。 |
| `403` | Tailnet grants 或出站主机策略拒绝；由管理员检查，不要把 `ANIMA_OUTBOUND_ALLOW_PRIVATE` 改成 `true` 作为试错。 |
| 浏览器提示 cleartext/HTTP 被阻止 | 改用 Tailscale Serve 输出的 `https://<machine-name>.<tailnet>.ts.net`。 |
| `/healthz` 正常但 Anima 查询失败 | 检查服务器日志、提供商 allowlist 和具体模型配置；健康检查只证明进程活着。 |
| 朋友能打开网页但连接测试失败 | 检查朋友是否命中同一 Tailnet、grants 是否只放行 443，以及是否拿到了自己的 token。 |

不要在公共群聊粘贴 token、API key、Google Cookie、订阅链接或完整 `Authorization` 请求头。
